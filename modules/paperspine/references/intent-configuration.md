# 首句意图到配置草案

PaperSpine 可以从用户启动请求中提取配置意图，减少重复填写。意图提取只
生成 **Agent proposal**，不能伪装成用户确认，也不能绕过 Web 配置保存。

## 提取顺序

1. 先读取用户首句及同一条消息中的明确约束，再读取已有任务配置。
2. 明确说出的目标期刊/会议、语言、工作类型和交付格式优先于推断。
3. 明确字段直接采用；有依据的工作类型、语言、格式建议也可预填并标成建议。
   未知作者事实和隐私授权不能推定。未指定研究范围时保留 `agent_decide`，
   不默认改为 `materials_only`。
4. 在宿主交接说明中简短解释关键建议及其原文依据，配置字段通过 proposal
   供 Web 展示和用户修改。新任务初始配置/材料保存前不开展依赖该确认的科研工作；普通恢复
   直接复用仍有效的已保存配置，不因恢复对话或换阶段再确认一次。

## 常用映射

| 用户表达 | proposal 字段 |
|---|---|
| “分析这些数据”“新增回归/实验”“需要研究分析” | `research_mode=required`；保存后执行适合问题的研究分析并保留真实方法与结果。 |
| “深入查文献”“充分学习同方向和目标期刊” | 加深相应公开文献学习，可建议 6+6；不因此把已有 `materials_only` 改为 `required`。 |
| “深度研究” | 结合全文判定：请求数据分析/实验时用 `required`；只要求文献综述时保持实际分析范围，不能以关键词推定新增实验授权。 |
| “只用现有材料”“不要新增分析” | `research_mode=materials_only`；仍可进行公开文献学习、引用核对和参考图阅读 |
| “让 AI 判断是否需要分析”，或未指定范围 | `research_mode=agent_decide`；保存后判断证据缺口、说明理由并执行必要且在授权范围内的分析，或说明现有结果足够。 |
| “投/投稿/submit to + 期刊或会议名称” | `target.status=known`、保存名称，并按期刊或会议名称设置 `scene` |
| “中文写作/中文稿” | `output_language=zh` |
| “英文写作/English manuscript” | `output_language=en` |
| “中英双语/双语版本” | `output_language=multilingual` |
| “已有稿件改写/按现有论文重写” | `workflow=rewrite_existing` |
| “从数据/材料写一篇论文” | `workflow=build_from_materials` |
| “核查”“独立审阅”“按意见返修”“转投适配” | 分别使用 `audit`、`review`、`revise`、`transfer`；核查/审阅不自动变成新成稿。 |

研究模式与文献学习规模分开解释。“深度研究”不授权上传私有材料、不自动
确认动机或图件、不保证目标期刊接收。用户同时给出自定义数量时，以自定义
数量为准；例如“深度研究，但同方向 3 篇、目标期刊 8 篇”不得覆盖成 6+6。

## 交互要求

提取完成后，宿主应在同一任务调用 `paperspine_save_configuration` 生成草案，
然后打开同一任务 Web 页面。页面必须明确显示：

- “AI 根据你的首句预填，尚未保存”；
- 识别出的目标、语言、研究模式和文献数量；
- 用户可以修改并点击保存。

当前公共配置 schema 没有逐字段推断理由字段，页面也未实现这项展示。
在宿主交接说明或现有任务笔记中简短说明关键建议及对应原文；不提交虚构字段，
也不声称页面已经逐项展示推断依据。

只有 Web 用户保存后，桥接文件才会成为
`source=web_user`, `user_confirmed=true`, `readiness.ready=true`。普通恢复沿用
同一任务仍有效的已保存配置、材料和选择。只有用户要求变更、明确新测试或
材料范围实际改变时，才核对受影响项；保留原设置和成果，不建立重复确认链。

## 不确定情况

“高质量”“像优秀论文”“多参考文献”等泛化表达可以作为写作偏好记录，
不能单独推断投稿目标、输出语言或隐私授权。没有明确的目标期刊时，保留
`target.status=unknown`，初始保存后由实际材料和公开文献形成适合的目标建议。
已有明确代选授权则在该范围内选择，否则只对未解决的目标决定请求用户输入。
