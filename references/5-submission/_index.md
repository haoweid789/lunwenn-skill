# 5 投稿与合规族

这个族混了三类事：**投稿动作**、**前置材料**、**选题与计划**。它们都发生在"写作之前或之后"，所以收在一起。

```
还没定题 ─┬─ 要快速出几个可做选题 ───── → brainstorm/
          ├─ 要深度对话找方向 ───────── → brainstorm-ideas/
          └─ 定了题要排怎么做 ───────── → plan/

要写非论文的材料 ─┬─ 开题/研究计划/基金本子 → proposal/
                 ├─ 专利 ───────────────── → patent/
                 └─ 实验记录 ───────────── → experiment-log/

要投出去了 ─┬─ 投稿材料整理 ─────────── → submission/
            ├─ 数据/代码声明 ────────── → data-availability/
            └─ 被质疑统计 ───────────── → statistics/

学科特殊 ─┬─ 社科 ───────────────────── → social-science/
```

## 十个模块

### `brainstorm/` 六步五选题 — 主干
**精华**：固定六步产出**五个不同**的选题，每个必须带三样东西：
1. 最新查新（真的有人做过没）
2. 具体知识增量（不是"更深入"，是"多知道什么"）
3. **最小验证路径**（用最少资源验证它成不成立）

第三样是分水岭。多数选题工具只给想法，这个给出"怎么最快证伪"。

### `brainstorm-ideas/` 苏格拉底式选题 — 保留
**精华**：先学你的背景（读你的论文、查你的方向），再找值得打的问题。对话式，不一次给结论。

**选哪个**：要快出几个候选 → `brainstorm/`；想被追问、想找人一起想 → `brainstorm-ideas/`。

### `plan/` 研究路线与时间 — 主干
**精华**：**筛 20 篇对标原始研究、全文读透，再直接排出任务和周计划**。不是给建议，是产出：
- 具体任务清单
- 先后顺序
- 近期周计划 + 后期阶段划分

**独有约束**：它读的是**原始研究**不是综述。综述告诉你领域现状，原始研究才告诉你别人实际怎么做、卡在哪。

### `proposal/` 开题与基金本子 — 主干
**精华**：**四层 QA 管线** + 可配置研究域。套用"研究计划/开题报告/项目申请书"三种文体，结构按资助方要求分派。

### `patent/` 论文转专利 — 主干
**精华**：三段递进 — 中文技术交底书 → 权利要求书 → 现有技术对比。分阶段门禁，每段过了才进下一段。

**前置建议**：先用 `1-literature/xray/` 拆出哪几个点真的可保护，再进 patent。不然会把整篇论文当发明写，权利要求写成摘要。

### `experiment-log/` 实验日志 — 保留
**精华**：三套编码规则 —— 实验 ID、样品批次 ID、设备代码。产出带 YAML frontmatter 的 Markdown，可接飞书与 Obsidian。

价值在**可回溯**：三个月后能查清这个数据是哪次跑、用哪台机器、样品第几批。

### `submission/` 投稿整理 — 主干
**精华**：六步 —— 清单核对 → 文件齐备 → 格式转换 → 声明 → 上传 → 回执。它带各刊的投稿文件清单核对表，漏文件是投稿最常见的退稿原因。

### `data-availability/` 数据与代码声明 — 主干
**精华**：FAIR 元数据 + 仓库选择 + **数据集引用格式**。这三样常被写成一句话糊过去，但审稿人会认真看。

### `statistics/` 统计审查 — 主干
**精华**：审稿人最爱挑的五处，一次查完 ——
1. 实验单元（n 到底是什么）
2. 重复（技术重复 vs 生物学重复）
3. 不确定性（误差棒代表什么）
4. 检验选择是否匹配设计
5. 图注里的统计是否与正文一致

第 5 处最容易被忽略，也最容易被抓。

### `social-science/` 社科选题论证 — 保留
**精华**：**五套状态系统不合成单一分数**。这个设计很反直觉但很对 —— 新颖性、可行性、证据强度、表达清晰度、与领域契合度是五个独立维度，强行加权成一个总分只会掩盖短板。附十二个写作自检红线。

## 坑

- **`brainstorm` 和 `plan` 不要连着用**。前者产出五个候选，后者针对**一个**题目排计划。中间必须有用户拍板选哪个，替用户选了后面全白做。
- `plan/` 要求读 20 篇全文，成本很高。课题已经很清楚时用不上，直接排任务就行。
- `statistics` 是审查不是计算。要实际跑检验去 `6-infra` 或数模那套统计模块。
