# 1 文献族 — 找到、读懂、读透

## 决策树

```
要干什么？
├─ 拿不到全文 ──────────────────────────── → downloader/
├─ 不知道有哪些文献 ───────────────────── → survey/
├─ 要写严谨综述/系统综述 ──────────────── → systematic-review/
├─ 要做深度研究（不只是找文献） ──────── → deep-research/
├─ 已经有一堆 PDF，想就它们提问 ──────── → paper-qa/
├─ 只要读透一篇 ──────────────────────── → paper-card/
│   ├─ 要中英对照 ────────────────────── → reader/
│   ├─ 要整篇中文版 ──────────────────── → translate/
│   └─ 要判它可不可信 ────────────────── → xray/
└─ 要沉淀成知识库 ────────────────────── → 见 6-infra/kb-build/ 与 kb-fetch/
```

## 九个模块

### `downloader/` 全文获取 — 主干
**精华**：四级降级路径 **OA → 出版商 API → 机构代理域 → 浏览器兜底**，每一级有前置条件和状态分类（成功/受限/需登录/不存在）。67 个文件不是模板，是各库的真实入口与机构域名表。

**独有之处**：它明确列了「不做的事」——不绕付费墙、不碰盗版源。遇到拿不到的，它告诉你怎么合法拿到，而不是想办法绕。

### `survey/` 综述 — 主干
这里**并置了两个同名不同物的 survey**：
- `survey/`（原 `literature-survey-skill`）：**四模式渐深** — intent（问清你到底要学什么）→ triage（这堆里有什么）→ deepen（这篇到底说了啥）→ synthesize（连起来是什么）。核心纪律是**一次只问一个问题**，不一次抛五个。
- `survey/` 目录内的 `sci-brain` 版本思路：**主题调研沉淀成知识库**，产出可检索的结构而不是一段散文。

**选哪个**：学生第一次入门 → 四模式；已有明确课题要建库 → 知识库版。

### `systematic-review/` 系统综述 — 主干
**精华**：把 **PROSPERO 协议变成可执行纳排规则**，然后两轮筛选（题目摘要 → 全文），每轮带双人一致性判定与分歧裁决。

**何时必须用它**：要投系统综述、要写明「检索策略可复现」。普通的"综述文章"不需要它，用 `3-review/literature-review/`。

### `deep-research/` 深度研究 — 主干
**精华**：13 智能体 / 8 模式的流水线。真正别处没有的是**三路扫描 WHY-HOW-WHAT**：分别回答「为什么这事重要」「别人怎么做的」「现在缺什么」，三路交叉才定位到真空白。带 deep-research → academic-paper 的交接协议。

### `paper-qa/` 本地 RAG — 保留
**精华**：PaperQA2（CLI `pqa`）对整个 PDF 目录提问，答案**带页码引文**，能主动梳出「共识在哪、分歧在哪、证据缺口在哪」三张表。

**跟 deep-research 的区别**：deep-research 出去找文献，paper-qa 只在你已有的本地库里找。后者更快更准但受限于库。

### `paper-card/` 单篇精读 — 主干
**精华**：四段固定结构 — 方法拆解 → **从实验到论断的证据链** → 局限 → 可延伸想法。第二段是关键：不是复述结果，而是检查「这个实验真的能支撑这句话吗」。

### `reader/` 双语精读 — 保留
图文表公式对齐，问答可溯源到原文位置。适合精读而非速读。

### `translate/` 整篇中译 — 保留
逐页译成**保留版式的中文图片型 PDF**。定位明确：只做阅读版。要可编辑的重建走 `4-figures/reconstruct-su7/`，要逐字审校走 `2-writing/polish/`。

### `xray/` 论文透视 — 保留
**精华**：先判论文类型（原创研究/方法/综述/临床），再套对应的检查表，评估证据强度、标记过度声称。论文转专利时靠它拆可保护点。

## 合并进来的

| 原模块 | 精华去哪了 |
|---|---|
| `nature-academic-search` | 检索能力并入 `survey/`；它的 **MeSH 策略构建** 与**引文影响审计**两个独有功能，写进 `3-review/ref-verifier/_index.md` 的补充说明 |
| `nature-shared`（检索相关 core） | 无检索专属内容，其 `core/` 是写作规范，已在 `6-infra/core/` |

## 坑

- **`survey` 的两个版本别混用**。四模式版是教学向（帮你搞懂），知识库版是产出向（帮你建库）。混用会两边都不像。
- `downloader` 第二步是机构访问，需要先配好机构域。没配就直接跳到浏览器兜底，别在 API 那一步反复试。
- `paper-qa` 的索引构建是重活。库小于 20 篇时直接读原文更快。
