# 0 编排族 — 整条链路怎么串

读这个族的前提：用户要的是「**整条流程怎么走**」，不是某一个具体能力。如果只是要改一句文字、出一张图，直接去对应族，别在这里绕。

## 先问三个问题

```
Q1 要产出的是什么？
   ├─ 一篇可投稿论文 ──────────────── → pipeline/
   ├─ 一项研究（结论可能不成熟） ────── → research-cycle/
   └─ 一个可自动判分的目标 ─────────── → autoresearch/ 或 flow/

Q2 有没有明确的验收标准？
   ├─ 有（能打分/能跑通） ───────────── → autoresearch/
   └─ 没有，靠人判断 ───────────────── → pipeline/ 的检查点机制

Q3 卡住的时候允许回退吗？
   ├─ 允许重来 ─────────────────────── → flow/（backjump 是它的核心）
   └─ 只能往前 ─────────────────────── → pipeline/（检查点在前，不在后）
```

## 四个模块

### `pipeline/` 十阶段状态机 — 主干
**精华**：research → write → integrity → review → revise → re-review → re-revise → final integrity → finalize。真正的价值不在阶段列表，而在两个机制：
- **适应性检查点**：不是每阶段都停，按风险决定在哪停
- **中途接入协议（Mid-Entry）**：用户拿着半成品进来，能判断从哪一阶段接

**什么时候读**：从零跑一篇论文，或接手一个跑了一半的项目。

### `research-cycle/` 七阶段研究循环 — 主干
**精华**：文献综述与**对抗式查新**（不是找支持你的文献，是专门找能打死你的）→ 创新设计 → **基线复现**（先跑通别人的再谈自己的）→ 创新实现 → 实验验证 → 分析迭代 → 论文写作。

**什么时候读**：做研究而不是写论文。它强制「基线复现」这一环，很多流程都跳过这步然后全盘皆错。

### `autoresearch/` 自动研究 campaign — 保留
**精华**：先造一个密封校验器（validator），再让 agent 循环尝试直到过线。关键在于 validator 必须**先于**尝试循环固定下来，否则会自我欺骗。

**什么时候读**：目标可自动判分（跑通某个测试、达到某个指标）。不可判分的目标不要用。

### `flow/` 自主搜索循环 — 保留
**精华**：decide → simulate → learn → **backjump**。跟 autoresearch 的区别是它允许主动回退到早先的决策点重来。带 preflight 门禁（不过门禁不进循环）和明确的终止条件。

**什么时候读**：一个硬目标直解不通，需要试错并回退。

## 原 `codex-research-workflow` 的精华去哪了

那份 9.7 KB 的「十环节路由表」是整个包的编排层，但它写在 module 里等于没接线。已把三块有价值的东西提到母 `SKILL.md`：
1. **十环节映射表**（表在母文件的「十环节状态机」）
2. **阶段交接单格式**（【已完成】【关键结论】【未决问题】【下一步】）
3. **五个高风险环节的额外红线**（选题/基线复现/统计/审稿回应/投稿，这五处出错代价最大）

## 坑

- **不要同时用 pipeline 和 research-cycle**。前者假设结论已定、目标是成稿；后者假设结论未定、目标是做出结论。混用会让它在「该不该回头改实验」上反复摇摆。
- 检查点不是越密越好。每停一次用户都要重新进上下文，成本比返工高。
