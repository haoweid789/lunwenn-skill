# 2 写作族 — 从骨架到句子

这个族里**有四种写作方法论并存**，不是冗余。它们对"怎么写论文"的答案不同，选错了会别扭一整天。

## 四种流派怎么选

| 你的处境 | 用哪个 | 它信什么 |
|---|---|---|
| 常规起草，要像 Nature 那样写 | `manuscript/` | 从作者给的证据出发，套 Nature 语料的章节范式 |
| 要从零重装一套完整流程 | `paper-pipeline/` | 12 个智能体分工，11 种模式覆盖从大纲到 rebuttal |
| 文字松、逻辑散，需要被管住 | `editorial/` | 每一处改动都要过文风审计门禁 |
| 结构不清，要一个清晰骨架 | `martinis/` | 七段模板 + 图/记号/句级三套规则 |

```
要写正文 ─┬─ 默认 ───────────────────── → manuscript/
          ├─ 要全流程/多模式 ─────────── → paper-pipeline/
          ├─ 需要被严格管 ────────────── → editorial/
          └─ 要清晰骨架 ──────────────── → martinis/
只要改字 ─┬─ 保事实润色/翻译 ──────────── → polish/
          ├─ 去 AI 味/加人味 ──────────── → humanize/
          └─ 句子段落不行 ────────────── → technical-prose/
要出别的东西 ┬─ 幻灯片 ───────────────── → slides/
             └─ 一个任务包到底 ─────────→ paperspine/
```

## 九个模块

### `manuscript/` Nature 语料范式 — 主干
**精华**：77 个文件是从 Nature 语料里拆出来的章节范式——摘要怎么压、引言漏斗怎么收、结果怎么逐级升级论断、讨论怎么反漏斗。它**从证据出发**：先问你有什么结果，再决定章节怎么写，而不是先给模板再往里填。

### `paper-pipeline/` 12 智能体重装 — 保留
**精华**：11 种模式（full / plan / outline / revision / revision-coach / abstract / lit-review / format-convert / citation-check / disclosure / rebuttal-audit）、8 阶段编排。别处没有的两个协议：
- **Generator-Evaluator 契约**：生成者与评估者分离，评估者不知道生成者的思路
- **修订补丁协议**：修订不是重写，是打补丁并可回滚

**代价**：最重。只在整篇从零开始、或需要多模式切换时才用。

### `editorial/` 编辑门禁流 — 保留
**精华**：两样东西别处没有 ——
1. **结构化头脑风暴**（它自称是技能核心）：写之前先做一轮结构化发散，不是直接开写
2. **强制文风审计门禁**：每一处 tex 编辑都必须过审，不通过不能提交

适合「内容已有、文字需要被管住」的场景。

### `martinis/` 七段模板 — 保留
**精华**：七段结构 + 图规则 + 记号规则 + 句级规则 + 投稿前清单。最清晰的一套骨架，适合结构还没成型时先把架子搭起来。

### `polish/` 润色与翻译 — 主干
**精华**：三条边界 —— **保事实、保术语、保证据边界**。它不会为了句子漂亮而悄悄改变论断强度。附 LaTeX 版式修复。

目录内并置了 `cell-manuscript-editing`（英文深度润色），它的独有价值是一张「**不可改变的事实**」清单——哪些东西润色时绝对不许动。

### `humanize/` 去 AI 味 — 主干
**精华**：**五维审计 + 体裁浓度表**。核心洞察是「人味的浓度随体裁变」：
- 论文：几乎不要人味，要的是精确
- 公众号/评论：要明显的人味
- 小说/叙事：要强人味

一套标准套所有体裁是错的。附自检三件套。

### `technical-prose/` 句段级写作 — 保留
**精华**：最轻量，只动文字不动结构。带一张 **hunt table**（该主动去找哪些坏毛病：名词化、被动堆叠、虚词、同义反复）。适合「结构没问题，就是读着累」。

### `slides/` 学术幻灯片 — 保留
Typst + Touying 可编译方案，输出的是代码不是拖拽文件。

### `paperspine/` 单任务闭环 — 保留
**精华**：研究、写、审、交付在**同一个任务内**完成，且支持**同任务回改**。167 个文件是模板与校验资产。适合"给我一篇完整的、能改的"。

## 淘汰的

| 原模块 | 为什么淘汰 |
|---|---|
| `humanized-writing` | 与 `human-voice` 同题（都是去 AI 味）。`human-voice` 的五维审计 + 体裁浓度表更深，且带 14 个参考文件。四场景分法已并入 `humanize/_index.md` |

## 坑

- **`polish` 和 `humanize` 会打架**。前者要求保术语、保边界，后者要求有个人痕迹。同一篇稿子不要同时跑。学术正文用 `polish`，科普/公众号用 `humanize`。
- `paper-pipeline` 的 11 个模式不必全用。多数情况只用 `full` 或 `revision`，其余按需。
- `editorial` 的门禁需要读全文才能审——稿子超过一定长度时成本很高。短稿才划算。
